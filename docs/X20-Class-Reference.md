# X20 native PDF classes

Output profiles are selected by their document class. M20 retains its existing
renderer and configuration. Other classes use source-mapped typography and outer
frame artwork with a shared native composition engine. These are native LaTeX
adaptations, with profile-specific decisions in `docs/profiles/*-source-audit.md`;
they do not claim complete pixel equivalence with every InDesign variant.

## Prepare and install

Original fonts and reference PDFs remain external local inputs. Prepare all
profiles present in the checkout from the supplied X20 directory:

```powershell
python scripts/prepare_profile.py --profile all --source-root "C:/Users/charl/Downloads/templates/WOD/X20"
python scripts/install.py --profile-root "C:/Users/charl/github/wodtex/inputs/profiles" --miktex
```

`--profile` is repeatable and can select one style instead of `all`. Preparation
checks the descriptor's source hashes, including ZIP members, and retains only
selected genuine faces and decorative frame strips under `inputs/profiles/`.
Each style has a separate resource directory, even when font filenames coincide.
No fonts or artwork from Downloads are modified or committed.

Installation includes every class with an explicit output descriptor. The
profile-root setting is stored in `wodtex-profiles-local.tex`, independently of
the existing M20 local configuration. Ordinary updates preserve both configuration
files. Supplying `--profile-root` explicitly sets the additional profile path.
Keep the prepared resource directory in place. On TeX Live, omit `--miktex`.

An external manuscript can then compile normally with LuaLaTeX:

```tex
\documentclass{c20book}
\title{The Dreaming}
\author{Author}
\begin{document}
\frontmatter
\maketitle
\makecredits
\tableofcontents
\mainmatter
\chapter{First Chapter}
\begin{sidebar}{Field Note}
This element uses the class's default style.
\end{sidebar}
\end{document}
```

Run LuaLaTeX until contents/references settle; run makeindex if using an index.
The generic metadata and element commands are the same as M20. Narrow and wide
sidebars have distinct widths and retain titles on continued fragments. Tables
outside sidebars use longtable with repeated header rows; nested sidebar tables
use native tabular. Host body text uses two columns, with full-width regions for
spanning components. IDs must be unique. Images resolve relative to the manuscript.

## Repository builds and verification

```powershell
$env:WODTEX_LUALATEX = "C:/path/to/lualatex.exe"
python scripts/build.py --target pdf --source examples/profiles/c20.tex --out build/c20 --verify
$env:WODTEX_X20_RENDER = "1"
python -m unittest tests.test_x20_foundation tests.test_x20_profiles -v
```

`WODTEX_LUALATEX` is optional when LuaLaTeX is on PATH. `WODTEX_PROFILE_ROOT`
selects an alternative prepared-resource directory for repository builds. The
native builder validates resource hashes, converges references/index, checks
glyph/font/reference diagnostics, and verifies measured page sizes. It uses the
selected class's descriptor and does not require the M20 EPUB toolchain.

New classes support native PDF. `output=epub`, `--target epub`, and `--target all`
fail explicitly for these profiles until an EPUB adapter exists. M20 keeps its
current PDF/EPUB route. Loading a profile adapter in a different host class also
fails explicitly; cross-host M20 components remain a separate extension task.

## Composition limits

Display sizes may be explicitly adapted to fit authored headings. Missing
matching faces have named, genuine-font substitutions in the source audits.
Clans, seasons, and alternative chapter variants are not automatically selected.
Outer page decorations come from audited PDF strips; interior sidebar/table/art
box composition is native and does not reproduce every illustrated frame.
Book covers are not generated by these interior classes.

These limitations are part of each profile's recorded contract and can be
extended independently without changing the shared manuscript interface.
